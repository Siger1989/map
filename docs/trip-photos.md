# 0.2.4-test：照片与轨迹时间匹配

后续源码修复（0.2.5，待原签名打包）：实走存档分类/原始时间保护、保存后进入照片页、失效轨迹选择回退及照片文件夹入口，见 [修复说明](recording-photos-fix.md)。以下下载链接仍是已发布的 0.2.4，不包含该修复。

“行程 → 照片”可以把拍摄时间对应到实走轨迹，生成地图照片记忆点。位置是根据轨迹推算，不代表读取了照片的 GPS，也不修改照片原始元数据。

## 使用步骤

1. 先记录行程并保存到轨迹，或导入含点时间的 GPX；当前未保存的实走记录也可选择。普通手绘线或道路规划没有真实拍摄时间轴，不能直接自动匹配。
2. 打开“行程 → 照片”，选择要匹配的轨迹，再选择手机照片。安卓使用系统文件选择器，可以一次多选，最多 30 张；只访问明确选中的图片。
3. 查看“可匹配 N / M 张”。读取的是 EXIF 原始拍摄时间与拍摄时区；缺少时区时按当前手机时区解释。若相机时钟有偏差，展开“校正拍摄时间”调整分钟差；正数表示照片时间向后移，亦可逐张修改时间。
4. 截图、转发图或经过处理的照片可能没有原始拍摄时间，需要手动补填。本版不使用文件下载/修改时间代替拍摄时间。
5. 点击“加入地图”只保存成功匹配的照片，未匹配照片留在列表继续处理。相同原图再次导入同一轨迹会更新预览，不生成重复记忆点。
6. 地图显示小照片；密集照片显示合并数量，点击后可上一张/下一张浏览，查看匹配时间、轨迹名称和估算坐标。照片页支持显隐全部地图照片；预览页的“移除预览”只移除本应用记录，不删除相册原图。

## 匹配规则

时间恰好等于轨迹点时使用该坐标；处于同一分段内两个连续点之间时按时间比例估算位置。前后点间隔不能超过两分钟，并拒绝明显不合理的移动速度。不跨越暂停分段、不跨缺失时间点、不向记录时段外延伸；相同时间对应多个明显不同位置时不自动选一个。

图标位置受 GPS 精度和采样间隔影响，不能当作拍摄位置的精确测量值。照片文件与原始轨迹不会被此次匹配修改；之后修改轨迹时，已经保存的照片位置不会自动重新计算，重新导入同一照片可更新匹配。

## 本机存储与格式

- 支持 JPEG、PNG、WebP；HEIC/HEIF 取决于手机系统网页组件的图片解码能力，不保证每台设备可用。无法解码时请从相册导出 JPEG 原片。
- 单张输入不超过 20 MB，每批不超过 30 张。逐张处理，缩略预览最长边 960 px，采用 JPEG 保存；预览按照片方向显示，不存储原始大图。
- IndexedDB 独立保存预览和位置关系，本机上限 200 张 / 40 MB。关闭再打开应用可继续查看；不依赖相册文件后续路径，也不会将原图上传到服务器。
- 照片暂不包含在已有 JSON/GPX/KML 存档备份里。清除应用数据或卸载会删除这些本机预览；请保留相册原图及带时间的轨迹，换机可重新导入匹配。
- 地图使用小图和按屏幕位置聚合，点击才展开预览，原 3D 控制器及轨迹跟随保留；地形裁切剖面仍停用。

## 实现与验证

新增 `modules/photos/`：EXIF 导入、时间匹配、事务存储、面板、地图图层与预览。通过 props 接入 OutdoorPanel / TerrainMap / app；Android 文件选择器根据类型过滤和多选模式返回所选 URI，系统返回键先关闭照片预览。不新增广泛相册权限，不改变轨迹格式。

使用 [exifr 官方解析接口](https://github.com/MikeKovarik/exifr#api) 读取选定 EXIF 标签；安卓多选遵循 [FileChooserParams](https://developer.android.com/reference/android/webkit/WebChromeClient.FileChooserParams)。exifr 7.1.3 是本轮唯一新增依赖。

测试覆盖真实生成 JPEG 的 EXIF 时间/时区、缺时间、断点、重叠歧义和日期线。浏览器在 390×844 / 360×780 检查实际文件导入、逐张补时间、匹配坐标、去重、EXIF 旋转、重载恢复、聚合预览、翻页、显隐和移除。测试照片为仓库中的纯色合成样本，不是用户私人照片。当前未连接 Android 真机，系统相册/文件选择器、厂商 HEIC 支持和实际触摸体验仍待设备验收。最终构建与签名结果见 [当前状态](../CURRENT_STATE.md)。
