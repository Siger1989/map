## 响应式约束

- 用CSS视口宽高，不使用手机截图物理像素；根安全区来自env(safe-area-inset-*)。
- 320–430宽竖屏：卡片宽度随视口变化，上下操作组固定贴安全区；不做整页transform缩小。
- <360宽：搜索优先伸缩；路线操作图标/文字上下排，摘要允许换行，保留完整操作入口。
- <=600高：减小底部留白、行程点滚动；同时>=600宽的横屏将记录窗移到右下内侧、右上三按钮横排，避开右下工具。
- >=600宽：卡片上限300，搜索上限380，导航内容最多600；地图继续占满可用区。
- 超长名称截断并保留title；数值缺失显示“—”；记录误差来自实际最近点，不伪造GPS/天气/预计耗时。
- 右侧预览按用户要求保持390×844；其他尺寸在独立检查页验证。

## 模块边界

- `modules/tracks/HomeRouteCard.tsx`：主页摘要与现有路线动作；高程读取复用现有服务，不写存储。
- `modules/controls/homeMap.css`：唯一主页规格；新卡片、记录窗、底栏和地图按钮不复用旧皮肤类。
- `RecordingQuickAction`：折叠与菜单不暂停记录；取消需界面内再次确认。
- `uiLayout/homeSelectors.mjs`：旧主页选择器和锚点在启动/导入时迁移到新组件，保留偏移/缩放/字号等值；不自动写回、删除或重置草稿。全新主页仍按此规格，用户自定义布局保留其偏好。
- 地图引擎、原轨迹/照片/标记数据、包名、签名和存储键不变。

视觉验收必须比较同尺寸参考与实际截图；构建通过不能替代视觉对照。模拟视口不代表所有手机或真机已验收。

## 避免重复问题的修改步骤

1. 先定位用户指出的控件及实际样式来源，只改相关组件。复用主页尺寸变量，避免在多个文件分别写位置。
2. 高度必须检查最终getBoundingClientRect以及computed min/max-height、padding、border和box-sizing；本轮天气height38却被旧min-height44撑大就是反例。
3. 居中要测四边：当前四个顶部白框y6、高38、底边44，背景高50；上下各6、整排左右各8。天气下方到3D为14，不靠目测宣称居中。
4. 背景放在统一底层，不用局部负z-index猜测层叠结果；截图后点开受影响入口，确认没有透明层截住点击。
5. 只检查这次受影响的尺寸/状态；涉及响应式或共享布局才扩展到320/360/390/430竖屏及横屏。保存关键截图，不反复堆积。
6. 按“修改→截图→用户确认”快速推进；不穿插额外重构、全量回归或出包发布。尚未确认的主页不能标成设计定稿。

布局类名变更需兼容已有布局选择器；不清空用户保存的位置来掩盖冲突。当前只维护主页，内部页等用户逐步确认后再做。
