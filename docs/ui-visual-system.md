# 山兔户外视觉系统（提案）

## 当前实现风险：改版前先处理这些边界

- **主页仍是浅色硬编码皮肤，与目标深色沉浸方向冲突。** [modules/controls/homeMap.css](../modules/controls/homeMap.css) 第2–19行定义了 `--home-ink/#10243c`、`--home-green/#15572b`、白色 surface、5px 边角、固定字体；第37、42、47、50、71、77、111、115行又直接写浅绿背景、白色卡片和3–5px圆角。路线紧凑样式 [modules/navigation/routeCompact.css](../modules/navigation/routeCompact.css) 第111–137行以 `!important` 固定白底、灰边、浅绿选中态。若只改全局变量，这些局部值不会自动换肤。
- **颜色与尺寸散落，存在旧皮肤覆盖。** 全局旧主题在 [app/globals.css](../app/globals.css) 第4–12行提供深海军蓝、青绿强调色；与首页自己的浅色令牌并存。记录控制台 [modules/outdoor/recordingConsole.css](../modules/outdoor/recordingConsole.css) 第10–65行重复硬编码白底、深绿、灰边、3–4px圆角及多条密度覆盖。优先将颜色/圆角集中到语义令牌，逐模块替换硬编码，避免在通用选择器上加一层新的 `!important`。
- **层级值没有统一总表，弹层有被盖住或抢点击的风险。** [modules/controls/homeMap.css](../modules/controls/homeMap.css) 第32–77行同时使用背景层 `z-index:4`、顶栏/定位/天气 `12`、地图动作 `60`、路线卡 `40`；第228–248行又加入实时信息 `80`、定位锁 `81`、收藏控制台 `82`，路线设置时定位 dock 升至 `71`。其他模块还各自管理图层。弹层、地图标记、导航工具和底栏可能出现跨 stacking context 的覆盖；视觉迁移应先列出地图内容、固定工具、面板、对话框、提示的统一层级，并用真实点击检查。
- **安全区与绝对定位混用，输入法/矮屏容易挤压面板。** 首页集中用 `--home-top/left/right/bottom` 与 `--home-footer`（[homeMap.css](../modules/controls/homeMap.css) 第8–18、71行）；但局部仍有 `top:0`、`right:48px`、`bottom:12px/104px` 等状态定位（第128、235、250–257行）。旧通用密度样式另用 `--safe-top/bottom`、固定 `56px/78px/128px` 偏移（[compactDensity.css](../modules/controls/compactDensity.css) 第80–82、108–115、145–153、199–207行）。变量名及预留口径不同，键盘缩小 visual viewport 后可能与底栏、地图工具或面板重叠。后续统一使用一个安全区/底栏占位来源，按 `dvh` 和实际 visual viewport 测量。
- **路线/行程面板依靠预留高度而非真实内容边界，扩展后可能相碰。** 首页路线卡、途经点、记录面板的高度分别受 `--route-card-clearance`、视口公式、`24dvh` 和200px上限影响（[homeMap.css](../modules/controls/homeMap.css) 第77、102、110–128行）；编辑/测绘/导航又有单独 clearance 覆盖（第205–218行）。[routeCompact.css](../modules/navigation/routeCompact.css) 第4–6、80–89行用固定高度公式和底部定位限制路线窗口。改卡片圆角、字体或间距会改变实高；不能假设原预留仍有效，要查看 `getBoundingClientRect`、computed min/max-height 和可滚动区域。
- **输入法有已知布局敏感点。** 主页路线重命名输入框字号16px（[homeMap.css](../modules/controls/homeMap.css) 第84行）；全局旧皮肤还定义多种小面板字号与 `max-height`。中文组合输入时需保留当前焦点行、固定关闭/返回入口、内部滚动并避开底栏；不能用压缩整页或再次缩小触控目标来容纳键盘。

本文定义渐进视觉规范，不授权大改功能布局。首页仍遵循 [homepage-ui-spec.md](homepage-ui-spec.md)，普通操作面板遵循 [ui-density-standard.md](ui-density-standard.md)；本规范补充统一的视觉语言。首页布局调整须先与用户逐屏确认。视觉参考是三屏户外应用的**设计语言**：深色沉浸、地图/照片主视觉、大圆角悬浮卡、少边框、荧光黄绿克制使用。不得复制参考图中的页面文案、功能、卡片内容、品牌或布局。

## 1. 设计语言

- 地图或现场照片占据主要画布；界面控件浮在画布上，保留连续、可读的户外场景。
- 深色半透明表面负责承载控制和信息。用明暗、间距、层级和阴影分组，减少连续描边与表格线。
- 圆润卡片表达一个当前任务；卡片内部一次突出当前步骤与主操作，次要信息折叠或进入下一层。
- 荧光黄绿只标出活动路线、当前位置、录制状态和主要确认操作。不要大面积铺底，也不要同时强调所有按钮。
- 户外照片使用完整宽幅或明确裁切窗口；地图保持可操作。照片说明、拍摄时间、方向/位置等仅展示真实已有信息，并清楚区分估计值。
- 保留山兔既有品牌资产 `public/brand/shantu-logo.png`，不从参考图仿制标志。数据来源、影像年份和许可署名应可读，深色主题不能降低署名可辨性。

## 2. 视觉令牌

以下为首轮样板建议值；落实时应建立 CSS 自定义属性，组件使用语义变量，不在各模块继续复制色值。颜色以文字对比和户外强光下可读为验收条件。

| 令牌 | 建议值 | 用途 |
| --- | --- | --- |
| `--visual-canvas` | `#08130F` | 地图周边/无图区域底色 |
| `--visual-surface` | `rgba(17, 28, 24, .88)` | 普通悬浮卡片 |
| `--visual-surface-raised` | `rgba(24, 38, 31, .96)` | 当前主任务、抽屉标题区 |
| `--visual-text` | `#F3F7EF` | 主文字 |
| `--visual-muted` | `#B8C4B5` | 次要说明、未选中信息 |
| `--visual-accent` | `#C7F36B` | 活动、选中、录制/导航强调 |
| `--visual-accent-pressed` | `#A9D64D` | 按下/深色表面上的强调状态 |
| `--visual-danger` | `#FF8175` | 删除、错误、危险操作 |
| `--visual-divider` | `rgba(235, 245, 232, .12)` | 必需的弱分隔线 |
| `--visual-focus` | `#D8FF8C` | 键盘焦点环 |

透明卡片须配合足够不透明度或轻微背景模糊，避免地图亮斑使文字失读；不依赖模糊作为唯一对比手段。路线强调色不得与危险红混用。

圆角按层级统一：主任务卡/照片抽屉 `24px`；普通浮卡 `20px`；按钮、输入框 `14px`；状态药丸 `999px`。卡片避免逐项围边；只在输入框、焦点态、必要分组和高风险确认上用描边。阴影以柔和向下扩散为主，弹层之间用层级区分，不用粗描边模拟悬浮。

间距以4px为基数：紧邻图标/标签4–8px，控件组12px，卡片内边距16–20px，卡片组间距12–16px。密度高的地图小控件可保留紧凑间距，但点击热区仍须不小于44×44 CSS px；列表行可按既定收藏36px密度规范处理。地图直接操作按钮保持44px热区。

字体沿用系统中文字体栈（当前首页为 `Noto Sans SC`, `Microsoft YaHei`, `PingFang SC`, `system-ui`），不下载未授权字体。建议标题20/24px、卡片标题16/20px、正文14/20px、辅助12/16px；地图浮层中避免低于11px。数值等宽仅在距离、时间、坐标对齐有帮助时使用。动态内容需截断或换行规则明确，缺值显示“—”，不可编造。

## 3. 组件规范

- **浮动顶栏：** 与地图边界保持安全区间距，背景轻透；搜索是主要入口，地图图层/天气摘要作为短小的圆形或圆角胶囊按钮。窄屏优先压缩搜索周围空隙，不遮挡输入焦点。
- **工具按钮：** 地图主操作用图标加短标签，常用项保持44px触控；活动项用荧光绿图标/小面积底色或边缘状态提示。不可只靠颜色表达选中/禁用。
- **任务卡：** 一张主卡说明当前任务，可拖/关闭时提供稳定抓手和明确关闭入口；卡片内容超过可视高度时只让内容区滚动，标题和关键动作固定。普通操作卡服从200px、最多300px宽的硬上限；路线基础表单/记录控制台等已有明确内容例外按既定主页规格处理，不以硬上限裁断必要表单。
- **列表项：** 尽量用留白和轻微表面差表达分组。路线节点、照片、收藏等行需有稳定点按区域、选中态和溢出处理；滑动操作提供可发现的按钮或提示，不能只靠手势。
- **输入控件：** 暗色输入框使用高对比文字和独立焦点环；字号至少16px以避免移动浏览器聚焦缩放。中文输入组合过程中不得过早保存半个字符或移走焦点；键盘弹出时按实际可视视口调整，主操作仍可达。
- **确认/危险操作：** 主按钮使用强调色；取消为低强调表面；删除用危险色并二次确认。一个卡片里最多一个实心主按钮。
- **照片卡：** 图片/现场画面为主体，元数据置于渐变或独立暗色信息区，不在图像上堆满图标；保证照片比例、完整查看及关闭动作清晰。

## 4. 地图层级与覆盖物

地图是第一层内容，不加整屏暗色蒙层。阴影/渐变只用于文字和控件后方的小范围可读性增强。建议统一 CSS 层级令牌：底图与数据层 `0–9`，普通地图标注/定位反馈 `10–19`，固定地图工具 `20–29`，操作卡 `30–39`，模态确认 `40–49`，全局提示 `50–59`。具体数值按现有 stacking context 审查后落地，禁止模块随意新增更大的整数。

同时可见时的规则：

1. 主页顶栏、右侧地图工具、底栏分别占据独立安全带；卡片不得覆盖它们的主要触控区。
2. 路线/照片/记录操作优先保留一张当前主卡。切换步骤时收起或替换前一张，避免路线表单、结果、天气、记录参数叠加成墙。
3. 路线本身保持地图上的高对比实线，起终点与当前定位用不同形状/描边；荧光色作为主路线或当前进度强调，备用/对比路线采用低饱和颜色并保留可辨图例。
4. 被卡片遮挡的路线范围要预留地图 padding 或提供“全程”视图；自动取景不能让终点埋在面板后面。
5. `pointer-events` 只作用于真实可点卡片。装饰底色、渐变、遮罩不能挡住地图平移缩放；交互层发生改变后实点检查地图拖动、卡片按钮和底栏。
6. 加载、离线、定位失败与无数据状态在地图上用小型提示表达，保留来源/精度语义；不能把离线图源或估计定位伪装成实时数据。

## 5. 安全区、输入法与响应式

- 基准预览为 OPPO Find X8 比例，390×约857 CSS px；窄屏另查360×780。截图物理像素不直接作为 CSS 宽度。横向空间足够时才扩成双列。
- 页面根视图填满可用视口；顶部、左右、底部安全区分别通过 `env(safe-area-inset-*)` 转成统一变量。底栏高度与底部 inset 合并计算，其他浮层统一引用 `--visual-safe-*`、`--visual-footer-clearance`，禁止各组件各猜固定偏移。
- 竖屏320–430px：地图满屏，顶栏弹性搜索，右侧工具保持44px热区，卡片宽度不超过300px且不侵入工具列，底栏保留原有五项语义与可达性。超窄时文字可换行，避免页面整体缩小。
- 高度小于600px或横屏：减少卡片外层留白、卡片内部滚动；把次要地图工具移入一组可展开入口，固定关闭/返回和主操作。地图可视区域不得低于现有功能需要的范围。
- 横屏宽度至少600px：可将路线/照片任务卡放在侧边，控制最大宽度并给地图留下连续画布；保持触控逻辑一致，不复制另一套业务页面。
- 输入法弹出：监听实际 visual viewport 高度变化，卡片底边以键盘上缘和安全区计算；焦点行滚入卡片内部。关闭/返回与保存/继续保持可达，底栏必要时隐藏后能稳定恢复，不能遮住组合中的文字。
- 浏览器模拟只证明该视口下的排版与交互，不代表 Android 真机输入法、安全区或户外强光已验收。

## 6. 路线规划样板页方案

样板仅规定“路线规划”已有工作流的呈现方式，不新增业务功能、不抄参考图中的文字或页面结构：

1. **默认地图态：** 顶部保留品牌/搜索/天气和图层入口，路线规划入口进入当前步骤。地图和路线仍是主要画面，右侧44px工具与底栏维持现有职责。
2. **输入态：** 单张深色圆角任务卡显示清楚的“起点”和“终点”字段、当前待操作一项、出行方式及主按钮。字段可搜索或从地图选点；选完起点后焦点转到终点。说明文案按需展开。表单不能与导航面板或完整结果同时常驻。
3. **规划态：** 计算中只在卡片内显示简短忙碌状态，不遮整张地图；失败时就地说明真实原因并保留输入。成功后收起完整表单，切换成紧凑摘要卡，地图自动显示路线全程且绕开覆盖卡片的区域。
4. **摘要态：** 主卡显示路线名称/类型、已有距离和可用耗时等事实数据，以及一个明确主操作“开始导航”；调整、分享、缓存等已有操作作为次级入口。详细天气、警告、逐段信息进入详情或按需展开。
5. **导航态：** 使用更薄的状态条呈现当前指引，保留退出和必要的展开入口；不默认与规划表单同时显示。路线线条、当前位置和下一个动作各有独立图形/色彩语义。
6. **卡片外观：** 采用深色半透表面、20–24px圆角、16px内边距、弱分隔、柔和阴影；荧光黄绿只突出路线、待操作字段和主按钮。实际高度需在390×857、360×780及矮屏测量，并与安全区、右侧工具、底栏一起实测。

以上只重排视觉强调和样式承载，不要求重写现有路线状态机、路线存储或地图图源。用户确认样板后再逐个推广到照片、收藏、记录等页面。

## 7. 全局推广顺序

按范围小、可单独确认的次序逐屏推进，每步只改当轮指定模块：

1. 建立全局视觉令牌和组件令牌映射，先完成路线规划样板；局部规则覆盖范围清晰，不能靠通配符盖住所有旧样式。
2. 根据样板确认地图顶栏、右侧工具、底栏和通用浮卡这些共享壳层；检查旧布局选择器和 `shantu.ui-layout.v1` 兼容，不重置用户布局。
3. 用户逐屏确认后，再分别迁移路线结果/导航、照片、记录、收藏夹、地图图层与设置。地图数据层、文件/照片格式、定位、路线状态和包兼容性保持原行为。
4. 每屏交付最小范围改动、必要定向检查、实际截图与用户确认；不在快速视觉确认阶段顺手做重构、全量测试、打包或发布。
5. 完成各屏确认后再做跨页面一致性与回归；视觉换肤本身不表示户外强光、设备触控、系统输入法或真机性能验收。

## 8. 单屏验收清单

- [ ] 本屏只实现已确认的视觉目标，内容来自山兔现有功能，未复制参考图文案/品牌/页面布局。
- [ ] 地图或照片仍是主体；必要的图源署名、照片信息、定位精度和估计值标签可读且真实。
- [ ] 使用语义颜色/圆角/间距令牌；荧光绿只强调少量当前状态和主操作；正文与底图对比足够。
- [ ] 顶栏、任务卡、右侧工具、底栏、系统安全区无重叠；关闭/返回、主操作和危险确认可点。
- [ ] 390×约857与360×780竖屏检查遮挡、横向溢出、面板实际边界和滚动；响应式改动另查矮屏/横屏。
- [ ] 聚焦输入并模拟中文组合输入，确认键盘上缘以上仍能操作，焦点行可见，关闭/返回固定，视口恢复后布局正确。
- [ ] 检查计算后的 `z-index` / stacking context、`getBoundingClientRect()`、computed `min/max-height`、`box-sizing`、padding/border；点按面板并拖动地图，确认装饰层不截获输入。
- [ ] 目视检查实际截图并保存至 `artifacts/screenshots/`；说明浏览器模拟与真机验收的边界。
- [ ] 本屏外功能、路线/轨迹/照片/标记数据与持久化键、`shantu.ui-layout.v1` 没有未经授权的变化。
