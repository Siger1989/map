# 山兔界面实施标准 · v1

状态：2026-09-25 用户确认首页与路线样板，并要求其他页面、子页面严格统一。本文件是当前 UI 实施与验收标准，覆盖旧文档中冲突的颜色、圆角、字号和预览尺寸；功能、数据与已确认布局约束继续有效。

## 基准与边界

基准截图：`artifacts/screenshots/ui-style-route-390-20260924.png`。地图为主要画布，深炭灰卡片、少描边、黄绿色主操作。迁移包括记录、画线、收藏与管理/导入/分享、工具、图层/图源、天气/时间、标记/模型、测量/剖面、照片、导航子窗口、帮助/个性化/布局设置，以及挂载到 body 的搜索与对话框。

保留入口、业务状态、保存格式、Logo、数据来源与署名。路线/轨迹颜色、地图图例、危险坡度、测量图、照片和导出画布属于业务内容，不能统一染成主题色。已有用户自定义配色继续生效；新用户默认使用本标准深色，恢复默认也回到本标准。

## 唯一令牌与组件规则

颜色唯一源为 `modules/appearance/theme.ts`，共享外观在 `modules/controls/outdoorTheme.css` 和 `outdoorSurfaces.css`。模块负责布局与业务语义，禁止新建另一套硬编码 UI 配色。

| 语义 | 默认值/规则 |
| --- | --- |
| 表面 /  raised | #18201f / #252e2b |
| 主文字 / 主色 | #f2f5ed / #d0f76b |
| 输入、次要字、分隔线、危险色 | 使用 --ui-field / --ui-muted / --ui-line / --ui-danger |
| 主操作文字 | --ui-on-accent；按实际主色计算对比度 |
| 卡片 / 控件圆角 | 20px / 12px；小分组10–12px；全幅内容页不强加外边距 |
| 标题 / 辅助文字 | 卡片14–16px；正文12–14px；紧凑辅助11px |
| 文本输入 | 至少16px；min-width:0；中文组合输入不抢焦点 |
| 触控 | 地图和主操作44px；密集表单/次级操作至少36px |
| 内部间距 | 4px为基础；已确认路线外框8px 10px；普通紧凑卡4–8px |

一张任务卡最多一个实心主操作；次要按钮用表面差，活动状态保留文字/图标与 aria 状态；危险操作用危险色。禁用态清晰可辨。选色器、图标样本等保留本身内容颜色。不要给每个数据项加边框，不新增装饰性大空白。

所有表单、按钮及子窗口的焦点统一为2px主题色内收线（outline-offset:-2px），必须完整落在控件可视边界内，不能覆盖邻接按钮。活动分组用弱底色和文字/图标表达，不与内部控件叠加第二层亮框；键盘焦点始终可见。贴边搜索行保留4px间距。联想没有候选时不弹空提示层，`aria-expanded`与实际弹层一致。图标加文字按钮必须在实际可用宽度下完整显示；空间不足调整排列或允许换行，不以裁切文字通过验收。

## 布局、安全区与滚动

右侧默认预览390×约857 CSS像素，OPPO Find X8 1256:2760，外围等比缩放；360×780与压缩高度检查使用独立页面。不得把物理像素当CSS像素，不得以压缩截图替代尺寸测量。

顶部60px、底部64px加安全区，地图动作44px。浮窗以既有 `--home-top/left/right/bottom/footer` 为依据，避免原生inset已消费后再计算一次。普通操作卡最大200px、最多300px宽，预留地图右工具；路线基础表单沿用已确认完整表单例外。内容页面保留以下已有尺寸例外，不能把它们裁成普通操作卡：

| 内容例外 | 既有实现与本次处理 |
| --- | --- |
| 首页收藏工作台 | `workbenchLayout.css` 最新覆盖为 min(52dvh,440px,可用高减236px)，保留该实际分屏；早期72%仅是旧规格，不能误改当前布局 |
| 图层浏览 | min(480px,62dvh,可用高减140px) |
| 帮助/个性化 | `help.css` 可滚动完整内容页，最高 min(680px,可用高减122px) |
| 收藏管理/导入 | 沿用独立居中对话框；导入最高 min(56dvh,480px)，管理保留焦点和内部滚动 |
| 照片、导航分屏、工程图/投影 | 内容画布按原布局；操作区域使用共享皮肤 |

外框限制可用高度，标题/返回/关闭固定，内容区 `min-height:0; overflow:auto`。不得让整个浮窗越过底栏或把关闭滚出视野。输入法压缩可视区域时焦点与主操作可达，不能仅缩小文字和热区。矮屏次要地图工具收纳，展开后避开3D、框选、相机及主面板；Esc和外部点击关闭。

保持现有经过验证的层级关系。新组件必须使用其宿主既有层级，不能任意加z-index；body portal必须继承根主题，保留现有焦点陷阱/关闭行为。装饰背景不接管地图事件。

## 执行与验收

1. 读 AGENTS、CURRENT_STATE 和本文件，盘点页面/子窗口与例外，说明本批范围。
2. 优先复用令牌和共享表面，修改必要模块。遇到旧 important 覆盖，在原规则改成变量，不无限叠覆盖；保留低风险兼容回退。
3. 每批实际打开主页面和子界面，检查 computed style、实际边界、标题、滚动、选中/禁用、返回及底栏；保存截图到 artifacts/screenshots。
4. 涉及尺寸检查390×857、360×780及390×480；极矮屏工具另查360×360。涉及输入/定位/相机的真机验收单独记录。
5. 执行类型检查、相关测试、移动网页构建与 diff check；不因纯视觉修改反复跑无关全套测试。输出 PASS/FAIL/BLOCKED 以及未覆盖状态，不能用构建通过冒充视觉或真机验收。
6. 更新 CURRENT_STATE 和页面覆盖表。用户已授权整批迁移，无需逐页再次请示；只有新增功能/改变已确认结构才提出具体差异。视觉迁移阶段沿用快速预览流程，APK/发布待明确交付。

未来所有新增及维护界面均执行此标准。新的明确用户指令优先；实际例外需写明来源、原因与验证，不能默默另设皮肤。
