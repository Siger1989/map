## 已完成与原因

1. 帧配对：旧实现可能把旧MVP与稍后读到的新相机/视口组合；现于当前RenderContext准备时捕获不可变元数据，再绑定同一实际绘制帧。
2. 拖动开销：旧MOVE先构造JSON再节流；现先判断门限，按触摸或绘制需要构造pointers，保留多指与取消契约。
3. 最高级：原生部分天地图层统一请求到19级，超出官方有效范围。已核对WMTS GetCapabilities：img/vec1–18、ter1–14、cva1–19、cia/cta/ibo1–18；到上限后继续放大最后级/祖先瓦片。
4. 自动持久缓存：旧64MiB临时目录不足以满足用户的大缓存要求。新增APP私有`filesDir/shantu-map-browse-cache/`，默认8GiB预算、SQLite索引/WAL/LRU，按实际浏览增长；不整包读入RAM，保留256MiB可用存储余量。
5. 多余请求：旧透明地名层仍可能下载，可见地名另走独立链。现停用透明旧层，可见天地图地名/境界与底图共用持久缓存及网络调度；过期可先显、后台有界更新，常规纹理精准失效。

未提高天地图当前4活动请求/250ms启动节奏；官方公开页面未提供适用于用户Key的准确QPS/单批下载上限，不能把本地配置当官方限制。
