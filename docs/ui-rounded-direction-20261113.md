# 山兔UI优化方向与建议 · 圆润、轻盈、地图优先

日期：2026-11-13。依据：用户本轮提供的komoot前后对比图，以及“这种圆润点的UI看上去年轻很多，后期还想UI带一点动态，不过那是后期”的明确反馈。

## 1. 已明确的方向与待比较的细节

**方向：年轻、圆润、轻盈，具备现代工具的清晰层级与操作效率。地图是主要内容，控件围绕当前任务组织。** 前两轮灰绿/科技深蓝配色试版均不是视觉定稿；后续不能以换主色代替布局、形态和交互优化。

本轮确认的是圆润方向和动效后置，未确认整套照搬参考图、纯浅色、某个主色、具体圆角/字号或将所有面板移到底部。后续同类组件、主图与双图统一参考这一方向。

原8px外框/4px控件是旧视觉基线；用户最新圆润方向允许后续试稿探索更大圆角，不应被旧数值锁死。具体数值先做同屏比较后再定稿。本轮仅整理文档，现有代码、用户主题设置与安装包不变。

## 2. 参考图中值得借鉴的关系

- 圆形图标按钮、胶囊主操作和圆角信息卡各有用途，形态能区分操作类型。
- 地图获得更多连续可见面积，面板退到边缘，主要操作仍能直接找到。
- 信息卡有摘要与详情层次，图表和文字有清晰阅读顺序。
- 单一主要动作更突出，返回、更多、图层等辅助操作减少视觉竞争。
- 界面轻盈来自分组、对齐和适当留白；复杂功能仍需可发现、可返回，不能仅通过隐藏入口获得简洁截图。

以上为针对用户提供图片的设计判断，不是对参考产品完整交互或性能的验收。参考图背景装饰、营销色块、手机倾斜摆放不进入山兔产品UI。

## 3. 静态视觉建议（先做）

| 部位 | 优化建议 | 试稿边界 |
|---|---|---|
| 地图主界面 | 工具按用途成组；独立图标按钮采用圆形或圆润方形，主要操作采用胶囊；减少连续厚底条 | 保留现有入口、44px地图命中目标与地图手势可用面积；不统一套大卡片 |
| 信息面板 | 外轮廓更圆润，采用轻阴影与有明确底色的表面；减少重边框及卡片内再套卡片 | 候选外框16–20px、矩形内部控件8–12px，仅作比较起点；独立圆形/胶囊按形态单独定义，不能机械扩大所有内角 |
| 图层窗 | 分为“当前图源”“常用显示”“高级参数”；图源入口视觉独立，开关与参数语义分开 | 功能全保留；常用开关仍直接操作。参数就近展开或在同卡片进入下一层，具体方式按实际步骤比较 |
| 字体与图标 | 标题、正文、辅助说明形成清楚层级；减少小字扎堆，提高图标可辨识度和统一笔画 | 不把所有内容缩小来塞满面板；原输入与标记紧凑例外分别验证，字号数值尚未重定 |
| 配色 | 同一布局做浅/深色对照：清楚的表面与文字、少量强调色、可辨认的关闭态 | 不预先锁死科技深蓝。品牌绿与冷青可作为强调色候选；Logo、路线/坡度/地质等业务语义色及已保存自定义保持 |
| 选中/关闭/危险状态 | 选中有颜色加形态/位置反馈，普通操作克制，危险操作保持独立语义 | “关闭”与“删除”不能同样处理；不靠降低可读性表现次要状态 |
| 图表和数据卡 | 摘要先读，详细指标按需展开；图表缩放时文字和操作区保持清楚 | 记录/导航关键状态持续可见，避让比例尺、摇杆、定位和底栏 |

圆润不等于所有区域变大。先通过分组与按需展示减少同时出现的控件，再分配字号和间距；保留地图面积及真实滚动可达性。

## 4. 交互建议（随结构优化）

1. **简单状态直接切换。** 保留已按用户要求实现的朝向点击循环，当前状态清晰可见。开关点击后立即呈现真实状态；不能显示未成功的定位或加载结果。
2. **常用操作少一步。** 地图、图层与记录的高频动作优先直接触达；低频参数放在明确的“参数/更多”入口。重要操作不能只靠长按或隐藏手势发现。
3. **一张面板只处理当前步骤。** 列表→详情→编辑沿用清楚的返回关系；尽量在同一面板切换，避免层层叠窗。关闭与返回的含义稳定。
4. **保持任务连续。** 菜单切换、关闭或收起面板不重置地图级别、用户角度、草稿、图源与记录状态；保留原跟随、隐藏UI/锁定约定。
5. **地图信息按需展开。** 摘要/详情切换需要明确可点入口。底部信息卡是可比较的方案，不能未验证就把全部现有面板迁到底部。
6. **变化有反馈、错误有恢复。** 保存、加载失败、权限未就绪有就近反馈；真实加载才显示进度。可逆操作按现有撤销语义处理，删除/清空规则不因改UI改变。

## 5. 动效建议（明确后置，当前不施工）

静态布局与交互稳定后，再增加少量服务于操作的动态：

| 场景 | 后期候选 | 约束 |
|---|---|---|
| 按下按钮 | 轻微按压与释放反馈 | 命中区域稳定，不延迟触发 |
| 面板展开/收起 | 短距离位移与淡入淡出，保持来源关系 | 不反复移动整张地图、不让用户等待动画结束才能操作 |
| 开关与模式切换 | 滑块/选中标识的连续过渡 | 真实状态先更新，动画可中断 |
| 保存/完成 | 短暂完成反馈 | 不遮挡下一步、不循环闪烁 |
| 加载 | 有真实状态依据的轻量进度反馈 | 不伪造百分比、不因装饰动效增加持续地图重绘 |

动画时长、缓动与触觉均后期再定。届时需支持系统“减少动态效果”、主/双图的连续操作及手机性能验证；低性能设备允许降低或关闭动效。当前不安装动效库、不引入持续发光/粒子/大面积背景动画。

## 6. 实施顺序与功能范围

**第一阶段：静态样板。** 用同一地图视角比较主页工具、图层窗和一张记录/导航信息卡，先判断圆润程度、信息分组与浅深色层级。保持业务内容完整；参考图不等于直接复制全部布局。用户审阅样板后再扩展。

**第二阶段：共享组件和交互。** 将已选样板落实为主题令牌、面板、标题/返回/X、图标按钮、胶囊操作、开关和分组规则。先覆盖主页/图层/图源，再覆盖记录、路线/导航、收藏、测量/剖面、标记及其它设置；主图与双图同步，独立编辑器逐项核对，不宣称未验页面已迁移。

**第三阶段：动态增强。** 在用户明确转入此阶段后，再按第5节加动态；不把动效混入当前静态试稿。

现有React UI与业务、原生地图和系统服务技术路线保持。图源/内置私人天地图、地图数据、定位与跟随、记录与暂停、导航、画线、测量、标记、收藏和数据格式均保留；本方案没有删除功能或重写地图引擎的授权。

## 7. 验收门禁

- 主视图390×857、窄屏360×780；新结构涉及矮屏时再验390×480，标题/关闭/返回可达，内容溢出必须真滚动，不裁掉功能。
- 主图与双图使用一致组件；卫星图、浅色矢量图背景下分别检查表面/文字/状态的可辨识度。
- 按真实步骤验证打开→切换→返回→关闭，检查地图视角、跟随、草稿、记录阶段和数据保留；不借外部位置冒充GPS。
- 留前后实拍，核对最终computed尺寸、触控区域、字体和层叠覆盖；构建通过不等于视觉通过。
- 用户审阅前保持候选标记。新APK、真机触控、GPU/性能与完整页面矩阵分开报告；按当前快速预览约定，不自动升版、打包、提交推送。
