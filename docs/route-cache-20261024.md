# 沿轨迹路线地图缓存 · 2026-10-24 快速预览

## 目标与范围

用户要求沿轨迹/路线缓存卫星图，开始前选择自定义图源，失去信号后可以手动显示缓存图像。用户已明确确认路线两侧各4公里（总宽约8公里），已设为默认；另提供各0.5、1、2公里。不是以单点为中心的圆，也不把整条路线外接矩形全部下载。

本轮属于现有山兔的快速预览阶段，目标沿用项目规则；不升版、出安装包、提交或推送。工作目录为项目根目录，分支 `codex/place-address-search-20261011`，基线 `cbb68b2`，远端同分支核对一致。开工已有未跟踪PDF、Playwright输出及Python缓存保留。

## 功能清单

- 收藏 → 轨迹/收藏路线三点菜单 → 缓存地图；自动带入所选路线。收藏分类增加“缓存区域”，全部分类也显示缓存区域及包数；点击进入包选择与管理。工具菜单不再放缓存入口。
- 收藏路线点击定位后保持收藏面板，可通过三点菜单进入缓存；详情/导航入口仍保留。缓存设置中也可切换当前规划路线、画线草稿、已保存轨迹或收藏路线。
- 两步设置：先选路线及已导入的在线图源，再选每侧宽度与最高级别，查看预计请求量和容量后开始。
- 点击开始后自动按队列逐张下载；可暂停、继续、关闭再进入查看状态。保持应用在前台，不承诺后台下载。
- 缓存包页可显示缓存图像、检查完整性、继续或确认删除。选中包后才允许开启仅缓存；提供恢复在线入口。
- 打开缓存图像是显式查看范围操作，会切换到包对应的图源并查看包范围。其它设置/返回/关闭不主动改变相机。
- 下载与离线查看都限于对应图源、路线范围及下载级别。放大超过缓存级别时复用最高缓存级别，不产生新细节。缺失瓦片不联网补图。

自定义图源仍使用其服务的请求额度、流量和许可。导入图源不是无限额授权。保留天地图批量下载暂停和OSM公共标准瓦片批量下载限制，包括混合图层和旧包续传。普通内置天地图及已有Key不删除、不改动。OSM官方规则见 https://operations.osmfoundation.org/policies/tiles/ 。

## 施工实现

新增 `modules/outdoor/RouteCachePanel.tsx` / `routeCachePanel.css`，通过 `CollectionsPanel` / `WorkbenchPanel` / `WorkbenchAction` 的路线三点菜单和虚拟缓存区域提供入口，`tabOrder` 增加缓存分类，由 `app/page.tsx` 组合路线、图源、`useOffline` 和 `useOfflineMapMode`。

复用 `importedRouteDownload` / `downloadPlan` / `offline`：分段走廊瓦片去重，坐标校正依赖补齐，单请求并发，暂停后扫描缓存只补缺失项，授权/429/网络失败立即停止并保留已下载内容。增加每侧4公里、@2x容量估算、续传来源复核及累计容量检查。每包上限20,000资源、1GiB，单瓦片8MiB，最多8包。

数据沿用本机 `guanyun-trips-v1` CacheStorage 和 `guanyun.trips.v1` 包索引；与轨迹和图源库独立。显式包URL索引按索引内容/包ID复用Set，避免每张瓦片重建索引。`tileCache` / `tileTransport` 读取选中包，缺失时仅缓存模式拒绝网络；MapLibre HTTP(S)的Source/Tile/Glyphs也受此模式约束。没有恢复旧版被动沿线缓存、路线删除自动清理或后台预取。

`TerrainMap` 应用离线最高级别上限，切换缓存模式刷新当前源。打开包的模式存储失败会回滚并显示错误；无有效包的旧离线偏好被清除。删除包复用旧包共享瓦片引用检查，不删除原轨迹。图源元数据仍是打开包的必要条件，源被删除后该包显示入口禁用。
