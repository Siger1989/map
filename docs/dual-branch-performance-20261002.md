# 双图轨迹分叉性能与错误恢复检查 · 2026-10-02

本轮针对用户反馈的双图编辑、分叉卡顿检查并修复本地源码。工作目录 `D:\天气地图`，分支 `codex/rollback-ui-0235-20260921`，HEAD `ec47ec0aa5f23cba6dfa2dd576197a82b6f34efe`。保留既有未提交修改；当前手机交付基线仍为 0.2.99-test/code106。本轮为源码与独立预览验证，未升版本、打 APK、提交或推送。

## 确认的问题及改动

- **分叉追加重复扫描元数据。** `routeEdit.appendEditBranch` 每落一点重建全路线的颜色、备注索引。新增 `branchMetadata.ts`，普通无重复边的路线按不可变快照的当前游标复用索引；撤销、重画、其它编辑导致游标所有者变化时重建；重复/反向物理边和同批重复边回退原有继承函数。保持 null 下一次继承采用样式色、严格 15cm 匹配、点详情、备注、来源路线不导入及历史快照语义。
- **两图重复构造相同线路。** `trackFeatures.ts` 按不可变路线及实际渲染条件复用线路生成结果，两张图分别持有自己的 feature、properties、geometry 外层对象；不共享可修改的图层状态。坐标仍按既有路线快照只读契约使用。
- **分叉一个点仍重发未变线段。** `TrackLayer.patchSingleTrack` 对同 ID 的 geometry/属性作比较，只 remove/add 变化的 feature，保持未变化图层索引及 worker 中的线段。新增 `trackFeatureDiff.ts`。样式、透明度、端点、点大小、预览取消、撤销均与完整渲染对照。
- **双图投影函数身份不稳定。** `app/page.tsx` 通过 `mapComparison/drawingMapProjection.ts` 稳定每个 pane 的屏幕投影函数；地图实例替换时重新创建，避免普通父组件渲染使吸附网格失效。`DrawingSession` 在有效视口 revision、候选和投影均不变时跨手势复用；没有可靠 revision、取消、外部 clear、视角/DEM/候选变化仍失效。
- **异步错误恢复遗漏。** 当前安装的 MapLibre `_dispatchWorkerUpdate` 会捕获 worker 失败并发出 source error，`updateData` Promise 可能正常完成。仅 `.catch` 的恢复分支无法覆盖此情况。现在监听对应轨迹/选择 source error，在微任务中恢复最新基线；每次显式同步每个 source 最多自动恢复一次，避免失败循环，源被替换时忽略过期恢复。
