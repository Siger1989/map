# 2026-10-01 图源加载调度第二轮

用户反馈“超强”三维地图有大片瓦片未齐、比奥维慢。本轮修复已确认的下载等待开销；没有手机或奥维的同机对照，不宣称两者速度已相当。

## 改动与原因

- `RasterCoordinates.ts` 原先在两个输出任务内逐张等待相邻输入瓦片，20秒期限还包含输出槽排队。现在取得输出槽后才启动20秒期限，输入交给 `sharedTileFetch.ts`，同一地图实例最多4个活动下载、96个等待任务；输出/Worker仍最多2个。
- 同一个 binding 和原始URL仅在下载尚未结束时共用一次请求，每个消费者取得独立ArrayBuffer，避免Worker transfer使其它消费者数据失效。一方取消保留其它消费者，全部取消才取消底层请求。失败、图源切换及无错误值的拒绝均释放状态，允许后续重试。
- `tools/map-tile-proxy.mjs` 给本地Node代理复用连接。协议、原主机名/SNI、已验证IP、地址族、端口共同决定连接池；每次请求和重定向仍重新验证全部DNS回答。每池最多4连接/2空闲，最多16池，空闲30秒淘汰，满池仅用一次性连接。取消或失败不销毁其它活动请求。12秒总期限覆盖DNS、排队、下载与重定向。真实排队测试首次失败：第5请求的25ms超时被Node延后到活动连接释放，耗时约5秒；修成主动拒绝和每请求幂等lease释放，复测通过。
- Node连接池属于桌面预览路径，Android原生Socket尚未加入连接池；公共JavaScript调度改动需要重新打包才能进入手机。Node Agent管理连接复用和数量上限的依据为[官方文档](https://nodejs.org/api/http.html#class-httpagent)。

没有改坐标计算、双线性/透明像素重采样、输出尺寸/清晰度、DEM的256px尺寸、用户相机/图层级别或数据库。没有恢复已移除的自动持久瓦片缓存；既有有界输出内存缓存仍为48项/16MiB。
