# 0.2.80 菜单与路线编辑性能调查

用户在 OPPO Find X8 Ultra 的 0.2.79 仍反馈所有编辑步骤、普通菜单点击、3D 导航卡顿。本版保留按钮、画面分辨率、DEM 256、数据格式和独立 APK 签名。以下是代码/浏览器/合成 CPU 证据，不能等同于手机帧率或真机验收。

## 已确认的重复工作

- Home 以整个 `panel` 作为路线 overlay 的依赖，即使没有路线指示点，打开工具菜单也会重建整份路线 overlay。标记、剖面列表和隐藏照片的空数组每次 render 重建，又触发无关地图配置。
- 节点选择保留几何，却让 TrackLayer 全量构建、索引、序列化保存路线。旧版还把当前活动点混在完整 GeoJSON 中更新。
- 没有任何备注的路线，每次仍生成边颜色索引、边备注索引、遍历边和顶点，最终输出空备注集合。
- 分叉只改变一条路线，却处理所有可见路线。仅缓存投影无法消除这个主要成本。

## 修复和边界

- 稳定派生路线/标记/照片/剖面输入，路线指示点只依赖实际显示值。选择清理结果相同时保留数组引用；路线颜色模式无需变化时保留原轨迹对象。
- 选点只 patch 旧/新节点活动属性，选中边仍独立更新。快照主动失效，后续全量还原不会错误跳过；预览复位、来源/图层重建、相机变化、地形变化、DEM 到达、resize 和 context 恢复均有保守失效处理。
- 路线没有备注内容时跳过全部坐标遍历；已有节点、路段和颜色备注的行为保持。
- 已实现受限的单轨几何差分。只有相机静止且静态呈现未变、同一轨迹集合中仅一个轨迹变化才复用背景；其他情况走完整重建。稳定 feature ID 配合 MapLibre updateData，异步失败恢复当前完整状态并重新应用当前拖动预览；来源被替换则忽略旧来源失败。
- 收藏数据相同 storage 对象及全部原始存储串未变时复用校验结果，返回独立深副本；缓存只有一条，失败不覆盖，存储变化立即失效。

## 验证证据

1. 浏览器隔离场景：2 条路线、1068 坐标、3 标记。打开一次工具菜单，修复前 routes/sections/models/annotations 各同步一次（路线5.1ms）；修复后四项均零增量。日志 `.openai/perf-0280-menu-{before,after}.json`。
2. 真实 UI：点选节点、进入分叉、点地图增加分支、撤销，反馈正确；点选一次路线同步1.1ms，标记/剖面/模型同步计数不增。时长是桌面 CPU 单次观测，不是移动端统计。日志 `.openai/perf-0280-node-browser.json`。
3. Node 合成：10 条各6000坐标、每条仅8个显式节点。旧版纯选点每次59990投影，12次完整manual-tracks更新；修复后纯选点零投影/零完整更新、12次局部更新。
4. 仅缓存投影的中间版：单轨几何变化由59990降至5999次投影，但整体约200ms只改善约1.3%，因此没有把它当作分叉问题已经修复。
5. 同规模无备注路线，备注生成独立基准中位65.85ms；判空早退后0.0018ms。现有连续路段/覆盖/节点备注测试和免坐标扫描回归通过。日志 `.openai/perf-0280-notes-{before,after}.json`。

6. 最终单轨差分基准：10×6000坐标，单轨变化中位26.9ms/p95 34.2ms，对照完整路径162.2ms/p95 186.6ms；每次投影5999而非59990，12次操作完整source更新由12降为0。非空新画草稿、相机/地形/显示变化仍有保守完整回退。
7. collectData 同规模数据缓存命中中位3.09ms，旧校验路径14.43ms；首次miss约17.19ms，增加约2.9ms缓存副本成本。
8. 最终707/707测试、TypeScript、Android构建、签名、zipalign、包内543网页文件/496地形PNG一致性PASS。最终浏览器菜单同步次数不增加；分叉新增2.6公里后撤销回0米、退出不保存PASS。截图 `artifacts/screenshots/route-edit-0280-final.png`，日志 `.openai/perf-0280-menu-final.json`。

## 天地图地名模糊

用户确认模糊的是天地图地名。当前 `domestic-labels-image/map/terrain` 是256px栅格注记（cia/cva/cta），文字在图片里，放大与3D贴地后会插值变软。源码检查显示底图锁级仅作用于底图，不同时锁住注记；正常在线模式无离线级别上限，默认WGS84不经过坐标瓦片重采样。没有把矢量文字halo调整算作此问题修复，试验已撤回。本版保持真实DPR，不降低画布分辨率；尚未改善天地图栅格文字本身的清晰度。

ADB 未连接手机，无法采集这台 OPPO 的 WebView 主线程/GPU trace。已确认的应用重复工作已修复；还不能保证这消除了用户手机所有长延迟。若新版仍有明显卡顿，下一步需要设备帧/长任务样本，不能用桌面 FPS 代替证据。
