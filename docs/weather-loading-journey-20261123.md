## 根因与修复

1. 行程允许请求天地图父级到 z8，准备/绘制/失败判断却只接受父两级。高清缺图但已有 z14 真影像时仍失败。`satelliteTerrainRenderer.ts` 统一覆盖范围；只有真实影像和 DEM 完整覆盖才能播放，低清状态保留，所有影像缺失仍失败。
2. 区域天气在缩放换网格时移除所有旧格，同时取消在途请求；整个批次返回前无天气，失败等待一分钟。新增共享 `weatherRegionStore.ts`，每批4点、最多2批并发，中心优先、逐批显示、按ID复用在途请求。过时排队任务不再启动，已经发出的请求有15秒超时。普通连接错误5秒后可重试，429有60秒冷却。有效缺测仍60秒复询。
3. 缩放新网格未返回时，旧数据只在其真实地理覆盖内裁剪显示，减去已覆盖部分避免重复雨雪；新区域不外推。正常12分钟刷新，刷新失败保留30分钟以内旧数据并标缓存，不把重试等待算成新鲜观测。
4. 原云绘制按每格固定数量和相似位置生成。改成共享地理云场、自然疏密/大小、缩放渐变和邻近已知云量过渡，晴格也保留供插值，缺测不参与；雨雪不做空间插值。云层4Hz更新并用离屏画布复用，雨雪仍按动画频率绘制。
5. 近景最小显示采样步长从0.0625°改为0.03125°，单视口仍最多32格，适配更广的省域范围；这是显示采样，不提高来源模型的实际精度。云团形状为模型云量示意，不是卫星观测云边界。Open-Meteo 多点/current 参数依据 https://open-meteo.com/en/docs 。

## 11 月 23 日续查：真实接口与加载耗时

当前私人网页 9174、API 3108 在线。Open-Meteo 本轮真实返回 HTTP 200。直连首次 1.14 秒，显式走本机现有代理的同请求一次 4.83 秒，未修改 Windows、代理、DNS 或接口供应商。Node 复用连接后，4 到 32 点的实际批次多数为 0.23–0.25 秒。该结果表明此前的连接故障当前可恢复，未确认先前超时的唯一网络原因。

主图先发中心 4 点，合并其余数据为每批最多 16 点，保持并发上限 2。单次连接超时上限 8 秒。失败暂停剩余队列，首次 5 秒后仅用 1 个小批次探测，连续失败适用 15、30、60 秒退避。HTTP 429 至少等待 60 秒，可读取服务端重试提示时遵守更长间隔。回到旧视野仍复用有效地理覆盖。长白山演示初始镜头不再被启动时的 IP 估计移走。

长白山两种尺寸的浏览器对照都使用真实天气，并以同样的方式禁用自动 IP 估计。每个版本每视口一次测量。天气查询窗口从首个天气请求发出开始，到最后一个首屏批次返回截止：

| --- | --- | --- | --- |
| 390×约857，应用815 | 5 → 2 | 1.81 → 0.93 秒 | 4.66 → 3.83 秒 |
| 360×780 | 7 → 3 | 1.97 → 1.05 秒 | 4.45 → 3.54 秒 |

两种宽度均实际点击缩小和放大并核对天气仍在。另一次 390 不拦截 IP 请求，天气查询窗口 1.17 秒，iframe 到全量天气 6.29 秒，说明冷启动和网络依旧会波动。模拟首批两次连接失败后，浏览器显示正在重试，5 秒后发出 4 点探测，最终从真实接口恢复全部 20 格。网络慢时恢复仍需等待实际响应。截图与 JSON 分别在 `artifacts/screenshots/weather-network-20261123/` 和 `.openai/live-weather-network-*.json`，底图外部瓦片仍有缺块，未据此验收底图。

行程天气动画按选中时段请求，保留当前起始小时和结束后一个整点，以覆盖云量插值和雨雪累计，兼容跨 UTC 午夜。能覆盖新时段的旧缓存继续复用。临时网络故障和 5xx 自动重试一次，取消请求和限流即时停止本次重试。青城山 8 点跨午夜实调，4 小时全部返回。压缩响应约 0.50 KB，原 168 小时约 1.87 KB，少约 73%。三组 API 往返时间有快有慢，证据支持减小数据量。
