## 修改与根因

1. 绿色点是地图选点标记，不是GPS。`TerrainMap.tsx`接入`selectionMarkerVisibility.ts/.css`：以当前地图中心、纬度、缩放和画布短边计算附近半径（短边对应地面范围×0.75，最低150m）；远处隐藏，靠近恢复，保留选中坐标。随move/resize更新，卸载解除监听。选点也服从山体遮挡。
2. 普通标记与照片被山体覆盖时使用MapLibre原生遮挡判定，隐藏且禁用点击；明确的地下模型说明沿用透视语义。涉及AnnotationLayer、PhotoLayer及相应CSS。
3. 延续暂停前的布局/几何优化：`markerLayoutCache`复用纯平移时的子元素尺寸，布局、字体、图片和transform变化失效；ResizeObserver按集合增量维护。`markerQueryGroups`合并重叠查询，`projectedPathBounds`排除不相交路径；每次更新复用相同几何的投影与路径索引。
4. `terrainProjectionScope`仅在一次同步遮罩更新内复用未覆盖点的原生回退缩放决策；已加载高程仍走原生采样，结束后恢复原方法，不跨帧缓存高程。内部能力不匹配时回退原逻辑。
5. 路线与道路遮罩在支持luminance且无旋转/透视时共享一张SVG，用短Blob URL、标记边界并集及精确路径去重，避免每个标记重复解析完整SVG。超过预算/不支持的transform整帧回退单标记遮罩；不截断路线。原有mask样式恢复，替换/卸载仅释放自己创建的Blob。`routeIconPriorityFrameMask`与Geometry负责此路径。
6. 实际发现预览监听忽略`**/.openai/**`，导致嵌套工作树源码不更新、旧模块一直留在Vite缓存。`previewWatchIgnore`改为相对活动项目忽略构建输出，放行本项目祖先目录的遍历但仍忽略旁支；9174已重启并验证真实文件修改能使响应更新。

未改搜索、第一人称导航业务、原生桥接、记录状态、用户数据、地形资源或包配置。撤回了无收益的跨标记投影缓存及视口收窄实验。

## 性能结果与限制

同一电脑Edge/GTX1660，390×857 CSS、画布1248×2400、DPR3.2；1万路线点、30标记、5照片，地形开启、80°俯仰、zoom9，每次8秒连续平移，保留全部遮罩功能。

| 最终三次对照 | 平均帧间隔ms | P95帧间隔ms | 最长长任务ms |
| --- | --- | --- | --- |
| 固定HEAD基线 | 331.94 / 206.84 / 198.78 | 483.4 / 350 / 300.1 | 451 / 330 / 310 |
| 最终工作树 | 91.29 / 88.88 / 89.26 | 166.8 / 166.8 / 166.7 | 190 / 175 / 175 |

证据：`final-before-three.json`、`final-shared-cropped.json`。三次平均值中位数206.84→89.26ms，约减少57%；仍有明显长帧，不能报告60FPS、流畅验收或手机同等改善。单位8秒内长任务总时长未同步下降，因为最终绘制更多帧：基线6395/6975/8034ms，最终6891/6789/6809ms。

早期after实验受Vite旧模块缓存影响，已舍弃其比较结论。关闭mask的诊断结果只定位耗时，不是最终方案。最终共享data URL实验比Blob方案慢，未保留。Node测试和GPU型号均不能代替真实手机FPS。
