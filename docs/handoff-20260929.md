## 2. 用户目前的产品要求

- 手机优先、地图优先，保持既有深色与强调色及已保存个性化；主要反馈设备是 OPPO Find X8 Ultra。
- 只收紧窗口、间距与空白，不擅自删改原有实际按钮或业务语义。选点前后保持一级编辑面板布局稳定，避免内部滚动。
- 横屏地图工具靠最右安全边，摇杆仍在右下；收藏夹左列表、右地图。竖屏收藏保持上下布局。
- 路线删除确认一屏显示；取消/确认及原操作保留。测试确认窗口时不要真的删除用户路线。
- 地图渲染性能、单指拖动、拖节点、分叉新增/结束、普通3D旋转都需要真机效果，不能用浏览器帧率替代验收。
- 使用 Luna 子 agent 并行处理可独立子任务；明确文件边界，主 agent 负责整合、实际预览和交付。
- 保留本机原数据、轨迹、照片、收藏、用户布局及同包名签名；不回退历史、不覆盖公司电脑成果。

## 4. 0.2.82 性能改动的具体边界

`modules/tracks/routeEdit.ts`：开启分叉仅追加单点段和必要的空颜色/备注行；结束已有实际线段的分叉只退出分叉状态；结束空分叉删除对应段和元数据行。既有几何、节点属性和未改行引用保留，继续走原有撤销快照机制。

`modules/tracks/TrackLayer.ts`：新增 `canPatchHandleVisibility` / `patchHandleVisibility`。在相机/投影缓存/source/layers有效且数据符合守卫时，仅替换显示状态变化的节点，复用路线线段；空差分不派发主source的worker更新。异步失败恢复最新基线；source已更换则忽略旧失败。相机移动、草稿新几何或不符合守卫的数据仍允许完整同步，不能写成“所有分叉操作彻底无全量更新”。

新增测试：`tests/route-edit-branch-inheritance.test.mjs`、`tests/track-branch-fast-path.test.mjs`。涵盖元数据与撤销、recorded/samples背景节点、与完整结果一致性、引用保留、失效回退和异步失败恢复。

同一桌面同步JS基准（10条×每条6000坐标）开启/结束空分叉由193.066/183.857ms降至2.004/1.880ms；相应主source `setData/updateData/project`计数为0。这不含完整React、真实worker、GPU或OPPO耗时，详见[性能记录](performance-0.2.82.md)。
