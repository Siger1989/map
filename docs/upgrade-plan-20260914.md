# 附图功能对照与接入顺序

附图用作需求清单与视觉参考，不把其宣传文案当作已有能力或设备验收。基线0.2.26；下列“本轮接入”仍须以CURRENT_STATE中最终验证/发行状态为准。

| 图中功能 | 代码核对 / 本轮结果 | 所属模块与下一步 |
| --- | --- | --- |
| 简洁低遮挡、二级信息折叠 | 既有300×200浮窗规范；新增记录模式折叠、分析折叠；仍有待整理的历史界面 | controls规范，各功能组件 |
| 定位坐标底部常驻 | 尚未按新图实现 | position展示组件，先做当前层级效果图 |
| 记录入口外置、高频操作贴边 | 本轮地图外置开始/暂停/继续/设置；编辑状态按需隐藏 | outdoor/RecordingQuickAction |
| 开始/暂停/继续 | 已有；本轮保留暂停分段和未保存记录保护 | outdoor/recording |
| 自动开始记录 | 本轮用户可选“开始导航时自动开始”，默认关闭；不覆盖待处理记录 | samplingPolicy + 页面导航启动组合 |
| 轨迹随时调色 | 已有单色/宽度/透明度；本轮补速度/坡度模式 | tracks/style、RecordingPanel |
| 速度着色 | 本轮接入；必须有逐点时间，缺失/异常灰色 | routeAnalysis |
| 省电/标准/高精度/自定义 | 本轮省电/标准/高频/自定义；高频不保证高精度，精度门槛独立 | samplingPolicy、Android SamplingPreferences/Service |
| 原地降频、移动恢复 | 本轮Android静止60秒请求间隔提高到至少15秒，可靠移动后恢复；尚无耗电实测 | 原生服务/纯调度规则 |
| 按距离记录 | 本轮可选；保留最小时间和精度筛选 | TS/Java采样规则 |
| 直接输入地点、途经点、排序 | 已有输入和途经点顺序编辑；图中的完整拖拽交互待按当前UI单独验收 | navigation/RoutePanel、stops |
| 路线吸附道路 | 已有在线规划与编辑吸附基础；不是离线全覆盖 | navigation/provider、tracks/roadSnapping |
| 路线再次编辑 | 已有；原始实走改线另存手绘副本 | tracks/routeEdit |
| 左侧可拖进度条 | 已有路线与标记里程轨道 | TrackJourneyRail、journey/scrub |
| 坡度着色 | 本轮对有逐点高程的轨迹接入；手绘无高程仍缺数据 | routeAnalysis，可继续接现有DEM采样提供器 |
| 最陡路段/危险坡段 | 本轮统计采样最大坡度、连续50米最陡坡度及≥20%连续窗口段数；尚未增加地图警示标记，不声称识别全部危险 | routeAnalysis配置/计算；风险图层后续独立 |
| 海拔、累计爬升、剖面 | 已有DEM高程图/统计；本轮不重复造一份 | journey/metrics、tracks/TrackColorProfile |
| 内置离线导航引擎 | 未交付；现有离线包是渲染瓦片，无法据此直接算路 | 后续routing provider接口、可计算道路图、区域下载及设备容量评估 |
| 偏航提醒 | 已有连续可靠定位判定与在线接回；断网不画假的可走道路 | guidance |
| 面包屑返航/车/营地/撤退点 | 记录分段与沿线指引可复用，专门返航流程尚未完成 | guidance的独立返程计划，返回目标只保存坐标/类型 |
| GPX/KML/KMZ | 既有支持；本轮格式解析独立，JSON按内容识别 | dataTransfer |
| 批量导入 | 本轮GPX/KML/KMZ/JSON混合最多10文件；全批校验后确认一次合并 | batchImport、TransferPanel |
| OVKML/OVKMZ、自动识别坐标系 | 尚未完成，不猜测坐标系。奥维官方说明可为GCJ02或CGCS2000；需要真实样例验证元数据与转换 | 新增独立坐标适配器，不污染存储层 |
| 天地图Key申请入口 | 既有环境配置/图源接入；新图所示应用内申请入口待加 | mapSources独立帮助组件，凭证不进入源码 |
| 实时位置/队伍/掉队/最后在线 | 尚未实现；没有队伍通信服务、身份与位置过期规则 | 后续team领域模块 + 可替换transport；先明确服务部署与分享权限 |
| SOS一键求救 | 尚未接通真实联系人/通信服务；不能用静态按钮冒充求救已送达 | safety模块，经确认分享求救信息并显示送达/失败状态 |
| PTT对讲扩展 | 尚未实现 | 独立语音传输适配器，按住期间采集，和定位传输分离 |
| 轨迹导入照片/拍照点关联 | 已有逐点时间匹配、拍照标记绑定和照片列表 | photos；原始时间/坐标保留 |
| 长图分享 | 已有地图/高程/路况长图；本轮地图线随速度/坡度模式渲染 | routeShare |
| 横竖图混排、重点照片放大 | 已有照片查看与导出基础；图示叙事混排版式待设计/实现 | routeShare的独立版式模块，不放主页面 |

后续按用户早期偏好，涉及新层级布局先给效果图。建议顺序：完成当前记录/分析/文件基础 → 当前地图主界面和返航 → 区域离线路由 → 队伍通信/安全 → 照片叙事分享。各阶段独立验收，不把接口占位或静态演示标成已上线。

参考：[奥维官方格式说明](https://www.ovital.com/139064-2/)、[Android定位请求参数](https://developer.android.com/reference/android/location/LocationManager#requestLocationUpdates(java.lang.String,long,float,android.location.LocationListener))。后者请求的是系统调度参数，不保证每隔指定时间一定返回一个定位点。
