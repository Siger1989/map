## 每场景交互性能硬门槛

各场景加载完成后，连续拖动、缩放、旋转60秒，重复3轮。每轮均须达标；双图分别统计主图和副图，不用三轮平均掩盖一轮失败。

| 项目 | PASS标准 |
|---|---|
| 实际地图显示平均帧率 | 每轮平均 >=30fps |
| 实际地图显示帧间隔 | p95 <=50ms |
| 长停顿 | >100ms 的停顿 <=2次/分钟；不得有 >250ms 的停顿 |
| 主副图联动延迟 | p95 <=100ms |
| 停手后的最终相机 | 200ms内主副图达到同一最终视角；记录相机、序列与时间，不能只看命令数量 |
| 单图不退化 | 相同条件下，候选的帧间隔与响应时间不得比原版本恶化 >10%；以各轮p95及同样测量口径对照 |

帧率与帧间隔针对持续交互期间的真实地图显示更新，不能用相同旧地图画面的重复提交、外围UI帧、SDK准备/绘制调用次数或桥接回调次数顶替。记录百分位算法、有效窗口、丢失事件和无效样本原因。

## 测量方法与证据边界

- 使用接近发布条件的优化构建，并核实所需profileable能力。低干扰粗粒度系统trace用于性能对照；全方法/ART详细采样仅用于独立归因，明确标注其扰动，不混入计时结果。
- 记录输入事件 → 主副图相机更新 → 数据准备 → GL提交 → 实际呈现的时间线；分别分析CPU运行、可运行但未调度、锁/其它等待、GC与GL相关阶段。后台GC整个持续时间不等于主线程暂停。
- 当前WorldWind 2.1.1实际是GLSurfaceView/直接GL路径。HWUI统计、Choreographer回调、Unknown Jank或SDK draw提交不等于地图实际呈现。先确认Surface覆盖和可用的真实呈现测量链路；测不到就记**未验证/受阻**，不能补零或判PASS。
- 真实呈现性能与录屏/截图、内存高开销采样、编译分开采集。保留原始trace及工具版本，不将录屏传输延迟当地图自身时延。
- 固定条件下进行AB交错复测，明确网络新增请求、冷热缓存、相机/数据差异与JIT/profile状态。局部节省、命令136对136等事实不能替代整体时延验收。
