# 山兔完整原生 Android 迁移：项目目标草案

日期：2026-10-27。状态：供用户确认的规划，尚未开始原生工程施工。

用户目标：做成完整原生应用，保留现有功能、已有数据和已注册内置天地图。首个平台按当前手机 APK 问题设为 Android；iOS、原生 HarmonyOS、Windows/macOS 全原生改造不计入本期工作量，也不取消原有平台需求。当前安卓交付基线是 0.2.141-test/code148，用户手机实际安装版本待核对。

## 1. 完整原生的定义

1. 首页、菜单、收藏、编辑、图源设置、地图及行业工具由 Android 原生界面/原生渲染组件承载。
2. 最终交付的上述流程不依赖 WebView、React DOM、MapLibre GL JS 或隐藏网页来运行；不会仅将壳换成 Kotlin 就称完整原生。
3. 定位、后台记录、网络、缓存、照片、文件、数据库直接调用原生服务。Java/C++ 库属于可用原生实现，不要求所有代码必须用 Kotlin 重写。
4. 既有 TypeScript 业务规则以算法/数据契约和测试样例为迁移资产，不假设网页组件能直接转成原生界面。

## 2. 用户可见目标

- 稳定打开和恢复地图；首图、高清补齐、网络错误及限流恢复具有可测量行为。
- 保留主图与双图的内置天地图，以及本机现有私人图源。不得以更换技术栈为由删掉图源或改为“我的图源”替代内置入口。
- 保留真实三维山体、路线、标记、照片和模型的地形关系；不得以平面图倾斜或地形晕渲冒充现有三维地形。
- 保留深色/黄绿色主题、原 Logo、紧凑布局、已确认的锁定/隐藏UI/导航跟随规则和用户个性化。
- 兼容用户存档和原包签名/身份。新引擎验证与迁移测试隔离进行，现有可用版本保留。
- 最终完成按功能清单逐条核销。分阶段版本允许尚缺功能，但必须明确标注，不能当作完整替代版。

## 3. 目前已知的关键约束

截至本轮官方资料核对，MapLibre Native 的 terrain 支持表仍将 Android/iOS 标记为未支持。因此“把 MapLibre GL JS 换为 MapLibre Native”不能直接满足现有三维功能；必须先验证其他原生三维引擎或评估额外原生渲染开发。出处见施工文档。

天地图数据与渲染引擎是两件事：保留天地图服务是目标，但现有 Key 的应用类型、原生请求使用方式及服务允许的缓存范围需核验。需要新增对应平台授权时，仍使用用户自己的注册账号办理，不通过伪造来源或轮换Key规避限制。

“原生”不保证上游永不超时或不限流。本项目对失败恢复、可观察状态及缓存命中负责；网络正常时才评估在线首图性能，故障场景单独验收。

## 4. 范围基线和变更

以当前交付源码、实际入口、存档格式和已有验收记录冻结清单；目录存在不等于用户可用。旧天气图层等被撤下或断开的历史代码先核对，不自动作为新增功能复活；未确定条目不得静默删除。

地图覆盖、图源授权、CAD支持格式边界和未验证原生能力保留原有说明。全球完整测绘覆盖、完整CAD编辑器、鸿蒙原生安装等不因迁移而自动承诺。

第一道可执行决定是是否按本草案启动“功能基线与原生三维地图验证”。引擎验证通过前，不承诺固定最终工期、不购买商业SDK、不展开全部界面重写。
