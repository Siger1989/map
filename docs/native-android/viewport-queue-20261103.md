## 原因与实施

SDK 2.1.1 的 `TiledVectorLayer.requestTile` 明确保留已启动的任务，最多登记128项；MVT在网络之后仍需解码与几何组装。仅给HTTP请求改屏幕排序，无法撤销仍等待重工作阶段的旧MVT任务。屏幕投影可失败，投影失败不能证明SDK认为瓦片不可见。

- `NativeTimedMvtLayer` 在SDK原加载方法之前加入每窗、每图层有界队列；上限使用既有 fetch+assembly 预算（常规图层3、独立吸附层2），保留SDK内部网络和组装信号量。
- 当前实际遍历结束后，撤销不在本帧访问集内、尚未获得许可的请求。先发送该SDK键的失效，再唤醒取消等待者；不生成网络失败回退。活动工作继续完成并进入原缓存，不逐帧终止正在解码的CPU工作。
- 使用实际帧MVP投影，屏幕中心优先，随后补齐可见边缘；SDK确认需要但投影不可算的瓦片排在有限末位，避免地平线漏图。没有待加载任务时跳过需求键记录和优先级计算。
- SDK最后一级会跳过 `effectiveDetailControl`。沿用本项目等高线的哨兵层办法，让真实最高源级14也被准确记录；该级返回无限细节阈值，停止细分。额外SDK层15不被请求，不改变源数据最大级、细节或样式。注意继承的SDK诊断属性 `maxZoom` 显示包含哨兵的值；复制图层使用原始源上限，不能逐次增加层级，并保留spriteAtlas。
- 关闭道路/地名/地形/独立吸附图层时显式取消等待项；延迟到达的SDK协程也会清理自己的等待项。已开始工作与缓存保留，重新打开可继续请求。
- 等高线队列拒绝非法rank；图层对SDK仍需的投影失败项提供有限末位rank，避免这项保护误伤合法瓦片。显示、采样、间距和几何预算不改。

## 用户追加：不必要资源尽量在解码前停止

首版3623803主要拦截尚未开始加载的工作，不能覆盖“开始读取时仍需要，但数据回来时已经过时”的情形。本轮针对这个缺口增加 `NativeMvtPredecodeSource`：

1. 原始缓存/网络读取前检查最新完整视口需求；非空数据返回后再检查，已过时或关闭图层就先使对应SDK任务失效，再取消后续流程。保留原始字节、元数据、负缓存、共享原始缓存及已有几何缓存，不做额外字节拷贝。
2. 对缓存命中的非空MVT，在返回SDK解码器之前按当前视觉中心再次排序。队列许可持续到该SDK请求的解码/几何组装退出，上限沿用该图层既有assembly并发值（当前1）；周边可见区域随后补齐。空瓦片与缓存未命中无需占解码许可。
3. 网络结果返回后只检查过时，不在 `fetchTile` 内等待这道缓存解码队列：SDK在source返回前持有HTTP许可，额外等待会让已下载边缘瓦片挡住中心的新下载。网络结果仍保留原SDK assembly信号量；加载前的中心优先队列继续生效。不可宣称所有网络结果已经在真正CPU解码开始的瞬间重新排序。
4. 完整需求集通过volatile不可变快照发布；新帧遍历尚未完成时继续使用上一个完整帧，避免空的半帧集误取消任务。解码许可按实际SDK coroutine Job归属，不按瓦片键归属，避免同键旧任务与重验证替换任务互相释放许可。
5. 关闭图层同时清理缓存解码等待项，已开始的同步CPU工作正常退出。clone先解包再绑定新实例回调，RevalidatingSource回调与close继续转发。只在显式诊断快照输出CachedDecodePending/Active及PredecodeDroppedCount，不增加周期采样。
