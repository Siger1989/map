## 原因与实施

SDK 2.1.1 的 `TiledVectorLayer.requestTile` 明确保留已启动的任务，最多登记128项；MVT在网络之后仍需解码与几何组装。仅给HTTP请求改屏幕排序，无法撤销仍等待重工作阶段的旧MVT任务。屏幕投影可失败，投影失败不能证明SDK认为瓦片不可见。

- `NativeTimedMvtLayer` 在SDK原加载方法之前加入每窗、每图层有界队列；上限使用既有 fetch+assembly 预算（常规图层3、独立吸附层2），保留SDK内部网络和组装信号量。
- 当前实际遍历结束后，撤销不在本帧访问集内、尚未获得许可的请求。先发送该SDK键的失效，再唤醒取消等待者；不生成网络失败回退。活动工作继续完成并进入原缓存，不逐帧终止正在解码的CPU工作。
- 使用实际帧MVP投影，屏幕中心优先，随后补齐可见边缘；SDK确认需要但投影不可算的瓦片排在有限末位，避免地平线漏图。没有待加载任务时跳过需求键记录和优先级计算。
- SDK最后一级会跳过 `effectiveDetailControl`。沿用本项目等高线的哨兵层办法，让真实最高源级14也被准确记录；该级返回无限细节阈值，停止细分。额外SDK层15不被请求，不改变源数据最大级、细节或样式。注意继承的SDK诊断属性 `maxZoom` 显示包含哨兵的值；复制图层使用原始源上限，不能逐次增加层级，并保留spriteAtlas。
- 关闭道路/地名/地形/独立吸附图层时显式取消等待项；延迟到达的SDK协程也会清理自己的等待项。已开始工作与缓存保留，重新打开可继续请求。
- 等高线队列拒绝非法rank；图层对SDK仍需的投影失败项提供有限末位rank，避免这项保护误伤合法瓦片。显示、采样、间距和几何预算不改。
