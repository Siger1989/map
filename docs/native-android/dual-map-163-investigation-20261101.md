## Continuation: exact contour endpoint stitching correction (C8 source change; no runtime acceptance)

- Source root cause: `NativeTerrainOverlayMath.stitchLevel` quantized each marching-squares endpoint with `roundToInt()` before constructing its adjacency graph. Endpoints less than a pixel apart could collapse to the same graph node even when their Float coordinates differed. The walker then emitted an artificial connector between those endpoints, changing the line geometry and multiplying short paths, their three-per-path logical-vertex overhead, and label-path fragmentation. This is a source correctness defect, not a confirmed standalone cause of the earlier phone exit.
- The minimal production correction uses exact Float raw-bit `(x,y)` identity, with `-0.0f` normalized to `+0.0f`. `contourSegments` evaluates shared cell edges in the same fixed endpoint orientation and operation order, so identical shared crossings should produce the same Float bits. The tests exercise unrelated sub-half-pixel endpoints, exact shared endpoints, closed loops, and real 3×3 neighboring-cell crossings; they compare undirected input/output segment multisets to prove each original edge is emitted exactly once, with no dropped or fabricated edge.
- Offline comparison used the same 17 of 32 unknown-owner candidate arrays that passed the current geometry preflight, at interval 30 m. In an offline clone differing only in node-key policy, paths fell 73,039→2,316; retained vertices 596,974→526,251; logical vertices 816,091→533,199; labels rose 275→339 as longer contours reconnected; SDK-style estimated content weight including fixed feature/label costs fell 76,539,888→55,704,184 bytes (27.2%). These arrays have no verified XYZ/tile ownership, so this is evidence of the mechanism on matching sampler-shaped arrays, not a production tile census or guaranteed resident-heap reduction. The byte estimate is the SDK's pre-assembly VBO/EBO estimate plus app fixed weights; it does not capture peak `FloatList` expansion or prove a 27.2% Java heap drop.
- Focused `:hybrid:testDebugUnitTest --tests com.shantu.nativeapp.map.NativeTerrainOverlaysTest` passed after the exact-key change. No APK was built/installed for this correction and no camera/memory qualification was performed. Do not report C8 as stable or as physical-phone acceptance; root's unified suites, integration, and controlled runtime proof remain separate gates.
