## A06 固定清晰度实际瓦片覆盖

1. 选择固定清晰度级别，确认相机中心、范围、朝向、倾斜完全不变。远景下低级别概览继续显示；概览层的最小级别不变、最大级别受固定值限制，不应因相机还未到固定级别而出现空白。
2. 小视野缩放到固定级别瓦片预算内，确认覆盖当前视口且状态显示实际使用的 z 级；把地图拉远或扩大范围，确认只铺最多 12×12 的中心清晰度，外围留同图源概览；任何拼图不得超过 144 个目标瓦片。
3. 移动地图跨固定瓦片边界，确认新中心图块更新；快速连续拖动时旧请求被取消、迟到结果不覆盖新视口；在同一个预算窗口内不重复启动同一拼图请求。
4. 切换内置天地图图层、自定义在线图源、离线图源和普通自适应模式，确认 detail overlay 使用当前 source 的真实 URL/投影与 tileSize，旧 source 图块不会残留；固定级别超出 source 范围时显示不可用状态，不以其他 z 伪报成功。
5. 开启双图，每张图分别验证当前视口拼图和固定值；销毁其中一图、暂停 Activity、离开页面后确认对应轮询和请求取消，不影响另一张图。缺网/仅缓存时保留概览、提示固定瓦片暂缺；不得把缺瓦片涂成成功。

## A03 离线缓存与共享网络池

1. 打开离线缓存面板，分别选择内置天地图和自定义图源；改变范围/级别/缓冲距离，确认请求总量估算、图源署名/配额说明及 250,000 张与 8 GiB 限制在开始前可见。超限任务应拒绝创建或开始，不能静默截断。
2. 开始一个小范围缓存，在系统通知中确认前台服务通知及暂停动作；离开缓存面板、切换菜单、旋转/重建 Activity 后确认任务仍由服务持有。暂停后确认已保存瓦片数不倒退，继续后从未完成资源接着下载。
3. 任务进行中强制结束应用进程，再重启。处于 `downloading` 的包应恢复为可继续的暂停状态，已写瓦片应跳过；检查包的 `completed/bytes/state` 与实际 tile 文件一致。
4. 两张地图同时显示并启动小范围下载。确认下载与地图读取共享同一个进程 loader、同 URL 只产生一个在途请求，关闭其中一张图不关闭另一张/服务所需的 loader；全部 owner 释放后再次创建 map/service 时可正常获得新 loader，旧 status callback 不再被强引用。
5. 对内置天地图观察 map 与下载请求均走同一 DataServer 类节奏：单一共享请求通道，发起间隔目标 250 ms，任一 `t0`–`t7` 的 429 会让同类后续请求共同冷却；map 有两条通用保留槽，等待中的 map 会排在下一条批量瓦片前，但不抢占当前正在进行的瓦片，也不突破共享通道。自定义图源应同时受全局 16 路和单 host 4 路批量预算约束。不得将测试结果描述为倍速或高并发；不能用真实授权 Key 消耗大范围配额。
6. 开启“仅缓存”后，缺失 tile 不应发出网络请求；已有离线包、长期离线 tile 不受浏览缓存 TTL 清理影响。关闭仅缓存后可继续请求。
7. 建两个包共享同一个 URL，删除其中一个包并确认另一个包仍可读；删除失败后仍可重试。确认没有删除浏览缓存、另一离线包或共享图源数据。

**源码复核记录（非运行验收）：** tile 请求调度为通用地图 2 并发槽、通用批量 16 并发槽；天地图批量最多 1 个 worker，且 map 与批量共享天地图单槽与 250 ms 节奏和 DataServer 类冷却，排队中的地图请求优先进入下一个空出的 DataServer 请求槽。一般自定义图源全局最多 16 个批量请求、每 host 最多 4 个批量请求，地图 2 槽独立保留；超出 64 个登记 host 后以共享溢出槽维持每 host 不超过 4。已为共享 Archive 容量原子性、关闭/仅缓存状态下迟到响应不落缓存、lease 关闭清理 owner callback 增加定向源码改动/测试；仍待主 agent 集中复编并执行上述服务/模拟器动作。

## A09 路线绘制与显示

1. 建一条多段路线；用节点选择操作批量选中并删除中间节点，确认断段/节点序号与路线几何按预期更新，并可撤销。
2. 在面板执行分叉、连接和合并各一次；逐项确认存在可见入口，操作针对所选路线/节点而非仅在模型中保存状态。检查误选/取消、撤销和重做。
3. 重新打开路线详情，依次切换并保存 `legend`、`statistics`、`profile`、`steep`、`coordinates` 五个显示项；退出重进确认 `shantu.route-display.v1` 设置恢复。坐标/高程以 `source.samples` 的高程优先，缺失时遵循旧版 `coords[2]` 规则；缺值保持缺失，不伪造为 0。
4. 检查路线展示图中的颜色分段、图例、统计与高程图数据；关闭每个显示项时对应内容确实隐藏。曲线手势缩放应同步缩放坐标范围，不缩放文字字号。
5. 主图和双图检查显示信息贴底栏上方 8 dp、右侧留 80 dp；纯速度图例贴底栏上方 4 dp，避让比例尺、右侧工具和摇杆。导航开启/关闭后按面板门禁恢复相应展示。

## A10 河流吸附

1. 以真实路线编辑草稿触发河流吸附，检查返回数据来源、匹配距离及服务状态；成功后应采用服务返回的实际河流几何，不能以端点直线伪造河道。
2. 在请求未完成时取消或切换目标，确认取消信号到达 HTTP 请求，旧响应不会覆盖当前路线；断网、无匹配或服务失败时保留原草稿并呈现明确失败状态。
3. 以公开/不含凭据样例做功能验证，不发起无界下载；检查吸附失败、跨断段与缺失数据不生成虚构高程或连线。

## A15 测量投影与剖面导出

1. 创建测量 A/B 测线，验证参考方向、测线偏距正负号、投影方向和断段规则与旧版一致。放置多个测站，确认剖面按真实站位和 DEM 采样显示；缺失 DEM 点保持空值/断段，不填 0。
2. 在地图分别增加、移动、删除测站，确认偏距、图上位置与剖面同步；取消/撤销动作不能留下半完成测站或破坏旧投影。
3. 从独立图件区域导出 PNG，确认 Android Canvas 图片有实际测线、投影/剖面、图例/测站数据及有效尺寸。检查导出文件能被图片查看器解码。
4. 导出中取消、DEM 采样失败、目标不可写时确认无半成品覆盖已有文件；再次导出同名文件前有明确覆盖/保存路径处理。
5. 勘探表单在 300×200 dp 普通操作浮窗内可滚动到达各控件；投影图件作为独立图表容器验收，不把整个表单扩大到超限尺寸。

## A16 摇杆与自定义布局

1. 相机摇杆验证 heading/pitch 手势、归中/结束拖动；处于 GPS 跟随时改变视角不得结束跟随或改变跟随状态。检查主图、双图和 44 dp 可触控区域。
2. 打开布局编辑器拖动、缩放并修改尺寸、字号、显隐、z-index、anchor；确认屏幕实时预览、撤销/重做、取消回滚和保存后重启复原。
3. 导入有效 `shantu-layout-draft v1` JSON 并逐字段核对；导入无效 JSON 应拒绝且保留当前草稿。旧 selector 做兼容映射，未知 selector 可被报告/跳过，不静默改绑到错误控件。
4. 锁定地图 UI 后确认编辑/恢复入口仍可达；解锁后继续导航检查角度跟随运行。确认编辑预览时没有退出导航/停止 GPS 跟随。
5. 使用系统文件选择器导出后重新导入，检查 JSON 字段、未知 selector 报告与恢复结果。分别在 390×857、360×780 检查安全区、底栏、比例尺、右侧工具、摇杆和路线图表无碰撞。
