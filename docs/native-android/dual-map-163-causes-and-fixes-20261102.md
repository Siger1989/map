## 原因与处理

| 原因 | 处理方法 | 保留的内容 |
| --- | --- | --- |
| 每个瓦片角点都重复重算相机、地形投影，双图进一步叠加，主线程忙于重复计算。 | 复用实际绘制帧的投影矩阵，同一XYZ只计算一次排序；双图快速投影通知与重地面采样分开，普通浏览安静180ms后做重工作。 | 当前视角、中心优先、定位跟随和真实编辑输入。 |
| 等高线把不同的邻近交点四舍五入到同一整数位置，错误拼接后产生很多碎路径。SDK每条路径还有额外顶点，导致渲染缓存工作集装不下，数据反复被淘汰、重建。 | 只连接完全相同的真实Float端点，规范化正负零；逐条核对输入segment恰好保留一次。 | 原DEM、等高距、全部输入边、宽度颜色；没有用抽稀或降低精度提速。 |
| 双图重复持有相同等高线几何，某些释放后的wrapper/回调还可能保留大数组；视野已变的未开工任务继续排队。 | 仅完整DEM样本哈希、XYZ与间距都相同才共享，按每窗lease计数并在最后释放时清引用；取消当前视野已不需要、尚未开始的任务。 | 两窗独立图层、已驻留内容和APP磁盘浏览缓存。 |
| MVT道路的多段线没有在新MoveTo分开，多条独立道路被误串成一条，出现假连接并占据点预算。 | 按官方格式分段，保留跨命令增量坐标游标；编码fixture同时检查多线、MultiPoint和Polygon。 | 全部真实源顶点、真实边和多边形环；不补假直线。 |
| 道路吸附快照混入7到14级父子路网，粗细整线重叠；LRU先后不保证细路优先。 | 选当前最高已有source-Z的同级瓦片，再按视野中心距离排序；保持24瓦片/6000点上限，并记录最高层是否完整覆盖。 | 原始缓存、网络和数据；未覆盖区域等后续真实瓦片补齐。 |
| 按点画线每次都把previous传null，原生端因此重新猜已提交点属于哪条道路。密集路口可能换错起点道路，出现绕回头路或limited。 | C12为每个原生runtime/generation/道路类型分别保留已提交锚点和未提交候选；只有坐标精确相同、当前源段与level未变才复用，并刷新当前screen位置。 | 真实断路和真正超限仍提示，不增加图搜索上限；旧Web逻辑不改。 |

| JS吸附投影把原始DEM高程直接当椭球高；原生地形还加了EGM96偏移。同帧五点测得约43m的高度基准差，屏幕位置偏4.64–4.73CSS像素，密集道路因此可能匹配到邻路。 | C13随原64×64地面网格桥接厘米级Int16偏移，投影和逆投影使用与原生一致的椭球高；先等待模型数据就绪，缓存身份包含模型实例，并严格校验尺寸/范围。实际安装C13同五点最大误差降到0.060673CSS像素。 | 原始DEM、业务海拔、显式绝对高度、实际地形和等高线数据；不通过降低精度或扩大吸附阈值遮掩错位。 |

| 节点和道路同时命中时，真实落点优先选节点，旧hint和preview.tip却优先显示道路。C13实测末点精确复用了14CSS范围内的已有节点，但提示仍写道路，造成显示与实际不一致。 | C14让points预览高亮、文字和松手落点都跟随实际胜出的节点；另分别验证纯道路和节点连接。 | 节点优先级、14CSS半径、全部候选、道路路径与原UI开关不变。 |

MVT分段依据：[官方MVT2.1规范4.3.3–4.3.4](https://github.com/mapbox/vector-tile-spec/blob/master/2.1/README.md)。高度基准调用链已核对本机实际SDK2.1.1源码；上游实现可参阅[WorldWind Globe](https://github.com/WorldWindEarth/WorldWindKotlin/blob/develop/worldwind/src/commonMain/kotlin/earth/worldwind/globe/Globe.kt)，该链接为上游develop，不冒充本机固定版本。
